# Seeker Shield: project spec

## What we are building
Seeker Shield is a mobile security checkup for Solana Seeker phone owners. It scans the user's wallet for risky token delegations, suspicious airdropped tokens and NFTs, and empty token accounts. It explains each finding in one plain-English sentence (AI), and fixes it with one fingerprint approval through the Seed Vault Wallet (Mobile Wallet Adapter). It then watches the wallet (and up to 2 friends' wallets, 5 with Pro) and sends Telegram alerts when new risks appear. Shield Pro is paid in SKR.

## Tech stack
- Frontend: React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui. Mobile-first single-page app, bottom tab bar: Scan, Watch, Profile.
- Server: Vercel serverless functions in /api (TypeScript, Node 20). All secrets live only on the server.
- Solana: @solana/web3.js v1, @solana/spl-token, @solana/wallet-adapter-react. Mobile Wallet Adapter via @solana-mobile/wallet-standard-mobile (register it as a Wallet Standard wallet). Network: mainnet-beta.
- Data: Helius RPC and DAS API (getAssetsByOwner). Jupiter APIs for verified-token status and prices. Check current endpoints in their docs before coding.
- AI: Anthropic Messages API, called only from /api. Model: claude-haiku-4-5-20251001. Explanations max 25 words, no jargon. Cache by finding type + mint.
- Database: Upstash Redis (via Vercel Marketplace).
- Alerts: Helius webhooks to /api/helius-webhook, then Telegram Bot API sendMessage.
- Android packaging: the Solana Mobile CLI `webshell` command (NOT Bubblewrap/TWA, which breaks MWA).

## Detection rules (deterministic code, never AI)
1. Delegation: any token account (both token programs) with a delegate set. CRITICAL if the account holds value over $1 or the delegate is on the scam list; otherwise WARNING. Fix: revoke.
2. Suspicious asset: token or NFT that is not Jupiter-verified AND has no price AND (name, symbol, or metadata URI contains a URL, "claim", "reward", "airdrop", "visit", or "free"). Label "Suspicious", never "Scam", unless on the scam list. Fix: hide (local), or burn and close only after an explicit second confirmation.
3. Empty account: token account with zero balance. CLEANUP. Fix: close account, reclaim rent to the user. Skip Token-2022 accounts that cannot be closed (e.g. withheld fees) and say why.
4. Scam list match: delegate, mint, or update authority on our scam list (Redis set, seeded from /data/scam-seed.json plus verified community reports). CRITICAL.

## Shield Score
Start at 100. Each CRITICAL -25 (max -75 total), each WARNING -8 (max -24), each CLEANUP -1 (max -10). Floor 0. Show the number and a word: 90+ Safe, 70-89 Okay, 40-69 At risk, under 40 Danger.

## Non-negotiable safety rules
- Never include the Seeker Genesis Token, SKR, SOL, or any account holding value in a close or burn instruction.
- Never burn anything by default. Burn needs a second explicit confirmation naming the token.
- Simulate every transaction before asking for a signature; if simulation fails, do not show the sign button.
- Show a plain-English summary of every transaction before the fingerprint prompt.
- Never request, store, or display a seed phrase or private key.
- Keep max 10 instructions per transaction; split larger fixes.
- Verify every webhook (shared secret) and every SKR payment on-chain before trusting it.
- Read-only by default: scanning never asks for a signature.
